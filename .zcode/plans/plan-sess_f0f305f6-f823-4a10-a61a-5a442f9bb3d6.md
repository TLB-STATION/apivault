## Plan: Local config + `apivault config` command + smart `run` defaults

### Goal
`apivault run --env production` (no `--` command, no `--key`) works by reading defaults from a local config file. Explicit flags always win; config fills the gaps.

### Precedence (the core rule)
| What | 1st | 2nd | 3rd | 4th |
|------|-----|-----|-----|-----|
| **Vault key** | `--key` flag | `APIVAULT_KEY` env | **config `vaultKey`** | interactive prompt (existing) |
| **Run command** | `-- <command>` | **config `run.command`** | — | error |
| **Environment** | `--env` flag | **config `run.env`** | — | error |

### 1. Config storage — `src/config.ts` (additions)
New file `~/.apivault/config.json` (next to existing `token.json`). Schema:
```json
{
  "run": { "command": "npm start", "env": "production" },
  "vaultKey": "mypassphrase"
}
```
New helpers: `readConfig()`, `writeConfig()` (file mode `0600` on Unix), `getConfigValue("run.command")`, `setConfigValue(path, value)`, `deleteConfigValue(path)`.

### 2. New `src/commands/config.ts`
```
apivault config set <key> [value]   # value optional; vaultKey prompts hidden if omitted
apivault config get <key>           # prints value (vaultKey shown raw here)
apivault config list                # prints all (vaultKey masked)
apivault config delete <key>        # removes a key
```
Known keys: `run.command`, `run.env`, `vaultKey`. Unknown keys also allowed (forward-compatible). `vaultKey` is masked in `list`, shown in `get`, and prompted with hidden input in `set` when no value is given.

### 3. Modify `src/commands/run.ts`
- `--env` → **optional**; falls back to `config.run.env`; errors if neither.
- If no `-- <command>` → split `config.run.command` on whitespace (quote-aware) into `[cmd, ...args]`; errors if neither.
- The vault key still flows through `revealKey` (updated below), so no change needed in run for the key.

### 4. Modify `src/commands/keys.ts` `revealKey`
One line — add config as the third fallback:
```ts
const vaultKey = (keyFlag ?? process.env.APIVAULT_KEY ?? getConfigValue("vaultKey"))?.trim();
```
This makes `keys get --reveal` benefit from the stored key too (consistent everywhere).

### 5. Register `config` in `src/index.ts`
Add `registerConfigCommand(program)` alongside the others.

### Security note
The vault key is stored in **plaintext** at `~/.apivault/config.json` — identical posture to the existing auth token at `~/.apivault/token.json`. File mode set to `0600` on Unix. It's opt-in: only stored if the user runs `config set vaultKey`. Users who prefer not to store it simply skip that step and the existing `--key`/env/prompt flow still works.

### No new dependencies
Reuses `@inquirer/prompts` (already a dep) for the hidden vault-key prompt, and existing UI helpers.
